# 定时任务模板（V5.1 实时回测）

这里是 V5.1 实时回测的 **6 个定时任务**提示词模板：关注池 4 个（盘中多点、13:32、15:02 收盘 K 线、18:35 收盘日报）＋ 重点池 2 个（盘中多点、15:07 收盘 K 线）。
每个任务是一个独立的 `*.md`，带 YAML frontmatter（`name` / `description` / `cron`），正文是**发给执行助手的完整提示词**。

> 任务提示词里的 `{{…}}` 是占位符，安装前必须替换（`python3 ../../scripts/install_tasks.py` 可以一次性渲染）。
> 提示词只教助手"跑哪个脚本、读哪个文件、怎么汇报"；**交易规则与参数全在脚本和 `references/` 里，提示词里不放规则**，所以改规则不用改任务。

## 任务清单

| 模板文件 | 触发（本地时间，工作日） | 做什么 | 池 |
|---|---|---|---|
| `v51-intraday-am-pm.md` | 10:02 10:32 11:02 11:32 14:02 14:32 | 每根 30 分钟 K 线收盘后跑扫描，汇报新买点/待执行/成交 | 关注池 |
| `v51-intraday-1332.md` | 13:32 | 13:30 那根 K 线收盘后的扫描（午休后第一根，单独成任务是为了不晚于 14:02 才发现信号） | 关注池 |
| `v51-intraday-1502.md` | 15:02 | 15:00 最后一根收盘后的扫描，**列次日 9:30 待执行单**及 9:25 取消条件 | 关注池 |
| `v51-close-1835.md` | 18:35 | 收盘流程：日线增量 → 档位 → 扫描 → （可选）TRIN → 日报与次日待执行单 | 关注池 |
| `focus-intraday-am-pm.md` | 10:07 10:37 11:07 11:37 14:07 14:37 | 同第一条，扫的是重点池，晚 5 分钟避免两个扫描同时压机器 | 重点池 |
| `focus-intraday-1507.md` | 15:07 | 同第三条，重点池 | 重点池 |

**为什么重点池只配 2 个任务**：账本是从起算日整段确定性重放，漏跑不丢记录；盘中任务多了只增加每天要读的回复数。代价是 13:30 那根的信号要到 14:07 才发现（晚约 37 分钟，超过一根 K 线，日报的"信号延迟记录"会如实标出）。**新建任务宁少勿多**——需要补哪个再加。

## 占位符

| 占位符 | 含义 | 例 |
|---|---|---|
| `{{HOME}}` | 工作区根目录（= `V51_HOME`） | `/Users/me/a-share-v51` |
| `{{SKILL}}` | 本技能的 `scripts/` 绝对路径 | `/Users/me/.claude/skills/chanlun-v051/scripts` |
| `{{PY}}` | Python 解释器（要装 pandas/numpy） | `python3` |
| `{{ADDRESS}}` | 汇报时对使用者的称呼 | `你` |
| `{{NAV}}` | 虚拟本金（仅重点池任务文案用） | `200000` |
| `{{FOCUS_START}}` | 重点池起算日 | `YYYY-MM-DD` |
| `{{FOCUS_N}}` | 重点池只数 | `100` |

## 时间与 cron

`cron` 字段是 5 段本地时间表达式。调度器若给循环任务加随机延迟（几分钟），属正常；**漏跑不丢账本**（重放是确定性的），只会让"信号延迟"变大。
应用/电脑睡眠或关闭期间错过的任务，醒来后可能集中补跑——同一秒同时启动多个任务时，注意本机并发上限（见 `references/11-incidents-and-pitfalls.md`：并发重进程 ≤3）。

## 汇报格式（所有任务共用）

收盘与 15:02 任务要求回复以单独高亮的 **【整理结论】** 开头（引用块＋粗体标题＋反引号包住核心结论），后面依次 **【依据】【推论逻辑】【数据健康与局限】**；
盘中任务用 **【结论】【依据】【推论逻辑】【数据健康与局限】**，约 12—15 行。要求"事实→规则→结论"，**所有数字必须来自脚本输出和报告文件，读不到就写"报告未提供"，不编造；不给投资建议，只做事实解读与规则推演**。

## 落盘（可选，推荐）

每次运行把最终回复原样写成 `journal/` 下的 md（文件名用本机时钟 `now.py` 取的时间戳）。这样漏看的回复事后能查，也能做"信号当时说了什么"的审计。
上传到笔记/知识库属于使用者自己的扩展，不在本技能范围内。
