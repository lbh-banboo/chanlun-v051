# 12 · TRIN（阿姆氏指标）观察插件

> **观察指标，不参与档位、买卖点和仓位**。V5.1 实时回测期不改规则，本插件不影响任何信号。
> 脚本：`scripts/trin_daily.py`（插件 2.0）；测试：`tests/test_trin_health.py`（213 项断言，合成市场）。

## 1. 口径

```text
TRIN = [上涨家数 ÷ (下跌家数 + 平盘家数)] ÷ [上涨股成交额 ÷ 下跌股成交额]
```

- 沪深 A 股约 5,200 只（**不含北交所**）；指数不计入；涨跌按日线 `pct`（交易所官方涨跌幅，除权日以除权参考价为基准）；成交用**成交额（元）**，不是股数。
- 口径来源：一档公开口播稿的公式写得不全，有两处没写清，用口播作者图上公布的 **5 个读数反推校准**：①「成交」用成交额而非股数（用股数算会差很多，用成交额 5 个读数全部对上，误差 ≤1.1%）；②**平盘股算在「非上涨」里**（家数比＝上涨÷(总数−上涨)，这正是口播里"红盘 80% ＝ 涨跌比例 4 比 1"的算法）；成交额端平盘股不计入下跌额。
- 这个口径是**由读数反推的**，不是原作者原话。对照口径（额剔平、Arms 原版用股数）与 4 日累计/平均版另有独立实现作对照，插件只输出主口径。

## 2. 如何读（和不要如何读）

- TRIN **随红盘占比机械联动**（历史样本相关约 0.6）：红盘占比极低的日子 TRIN 往往偏低，所以**单看绝对值容易读偏**。插件输出的「同广度对照」一行把今日放进"红盘占比相近的历史交易日"里排位，用来抵消这个联动。
- **作者的读法**（TRIN 低＝上涨票放量＝可能冰点）与**通行读法**（TRIN 极低＝超买）相反；本机**没有做全历史检验**，历史库只有最近一年多的日子。所以插件**只给事实，不下结论**：不写"冰点""超买""可满仓"。
- 把"红盘 <10% 且 TRIN <0.35"操作化后，217 个交易日里只有 3 天符合，样本太少，不构成可用信号。

## 3. 输出协议

> 以下为**格式示意**，日期与数值均为占位符，不对应任何真实行情。

```
TRIN_PLUGIN=2.0
TRIN_STATUS=OK|WARN|STALE|PARTIAL|ERROR date=… today=… [msg=…]    内部记号，任务不要写进回复
TRIN_CORE_1=> **【阿姆氏 TRIN】**（观察指标，不参与档位/仓位） `<日期> TRIN <读数>`｜红盘占比 <X>%（涨<N1>/跌<N2>/平<N3>）｜上涨股成交额占比 <Y>%｜较前日 <Δ>（前一日为 <读数>）｜历史分位 <P>%（10日，样本偏少分位不稳）｜数据源：新浪快照
TRIN_CORE_2=> 同广度对照：红盘占比相近的历史 <K> 个交易日（不含今日），TRIN 中位 <M>（区间 <A>–<B>）；今日 <读数> 放进去由低到高排第 <i>/<K+1> 位。
TRIN_HEALTH=TRIN 数据健康：<日期> 个股 <N> 只齐全（参考 <N_ref>）；数据源：新浪收盘快照（<时刻> 入库）；近 10 个交易日无缺漏；涨跌幅与收盘价方向核对 0 只不一致；成交额单位核对通过；与历史库对账无变化
TRIN_LINE1 / TRIN_LINE2 / TRIN_CHECK / TRIN_HIST / TRIN_FILES / TRIN_APPENDED / TRIN_ELAPSED
```

任务只取 `TRIN_CORE_1`、`TRIN_CORE_2`（已带 `> `）原样放进回复最上方的【整理结论】块，`TRIN_HEALTH` 放进【数据健康与局限】。

## 4. 状态与健康检查

| 状态 | 含义 | 核心结论里 |
|---|---|---|
| OK | 最新数据日 = 今天，所有检查通过 | 数 + 数据源 |
| WARN | 算出来了，但有下面任一项异常 | 数 + `｜留意：…` |
| STALE | 最新数据日 ≠ 今天（今天非交易日，或日线库没更新到今天） | 最近可用的数，标"（非今日数据）"和原因；不写日报 |
| PARTIAL | 最新一天个股只数 < 参考×0.97（日线库只更新了一半） | "未算出"+ 原因 + 最近一次可用的数；什么都不写 |
| ERROR | 目录不存在、历史库损坏等 | "未算出"+ 原因；exit 0 不拖累收盘主流程 |

**WARN 的触发项**（阈值用历史交易日标定）：窗口内某天个股不全；更新日志显示该日 15:30 前就入库（疑似盘中价）；`pct` 方向与收盘价涨跌方向不一致 >0.5%；量额收盘价与上一行完全相同 >0.5%（疑似没更新/复制昨天）；成交额÷(手×100×收盘价) 中位数不在 0.9~1.1（单位错）；全市场成交额不在前几日中位数的 0.35~3 倍；与历史库对账某天个股数差 >5 只或 TRIN 变动 >1%；沪深300 跌 ≥1.5% 而红盘占比 ≥80%（或涨 ≥1.5% 而红盘 ≤12%）。
数据源判定看行格式：新浪收盘快照入库的行换手率有 ≥4 位小数，搜狐日线补数的只有 ≤2 位（区分干净）。**搜狐补数日只作信息提示，不降级为 WARN**（系统本来就常靠搜狐补数）。

## 5. 流程位置与产物

`close_pipeline.py`（日线→档位）→ `v51_scan.py`（出日报）→ **`trin_daily.py`** → 任务读输出并回复。**必须在 `v51_scan.py` 之后**：它每次整份重写日报，先写会被覆盖。

| 产物 | 位置 |
|---|---|
| 回复最上方两行 | stdout → 任务原样放进【整理结论】块 |
| 一句人话健康说明 | stdout → 任务放进【数据健康与局限】 |
| 日报顶部块＋末尾小节 | `live/reports/V51_今日.md` 与首行日期也是今天的 `V51_latest.md`（`<!-- TRIN:TOP:BEGIN/END -->` 与 `<!-- TRIN:BEGIN/END -->` 标记，已有则原位替换，重跑幂等；标记不成对或日期对不上时**不动文件**） |
| 当天存档 | `pipeline/TRIN_YYYYMMDD.json/.md` |
| 历史库 | `pipeline/trin_state/trin_history.csv`（首次运行从最近 10 个交易日起步，之后每天增；分位要攒够 60 天才稳，之前输出会标"样本偏少分位不稳"） |

已知局限：次日第一次盘中扫描会重写 `V51_latest.md`，顶部块随之消失（按日期命名的 `V51_日期.md` 保留）；不含北交所。

## 6. 验证

- `tests/test_trin_health.py`：合成 300 只 × 30 天的小市场，逐项注入异常——TRIN 数字与测试独立算的真值逐日对账（含平盘）；每一项健康检查都能抓住对应异常；无论什么状态核心结论每天都有；报告里不出现 `TRIN_STATUS`；日报上下两块幂等、遇到异常标记不动文件；源码符合 Python 3.8 语法。
- 另做过"变异检验"（故意改坏 25 处：公式、每项检查、状态分级、核心结论缺失、日报写入、数据源判断…），全部被抓住。
