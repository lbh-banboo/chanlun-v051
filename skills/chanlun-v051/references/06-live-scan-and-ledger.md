# 06 · 实时扫描、记账与日报

> 脚本：`v51_scan.py`（关注池）、`v51_scan_focus.py`（重点池包装）、`pool_watch.py` / `pool_watch_report.py`（只读遍历）、`week_replay.py`（情景回放）。

## 1. `v51_scan.py` 做什么（一次运行）

```
取数（新浪主、东财备，4 线程）→ 写 live/state/m30_ext/<代码>.csv（只追加已收盘 K 线）
  → 逐只载入：历史 m30 + m30_recent + m30_ext 拼接去重 → 乘日线 adj 得前复权 → S 引擎 run_series
  → 从 start_date 起按时间戳逐根重放（成交、八道闸门、四个卖出条件、T+1、跌停顺延、档位、熔断、冷却期、主题簇 30%）
  → 写 live/state/v51_ledger.json、signals_log.jsonl、live/reports/V51_<日期>.md 与 V51_latest.md
```

**重放是确定性的**：同一份数据同一结果。所以补跑、漏跑、半夜电脑睡过去，都不丢账本记录；首次发现某信号的时刻写进 `signals_log.jsonl`（`delay_min`＝首次发现距该根 K 线收盘的分钟数）。

**命令行**

| 参数 | 作用 |
|---|---|
| `--no-fetch` | 不联网，用已存数据（沙箱/回放用） |
| `--asof "YYYY-MM-DD HH:MM"` | 以该时刻为"现在"（只用此刻之前已收盘的 K 线） |
| `--start YYYY-MM-DD` | 覆盖配置里的起点（情景回放） |
| `--tag NAME` | 输出写到 `live/state_<NAME>/`、`live/reports_<NAME>/`，**不碰正式账本** |

**环境变量**（第二个池）：`V51_POOL_FILE`、`V51_CFG`、`V51_TAG`、`V51_LABEL`；`v51_scan_focus.py` 是把这四个设好再原样运行 `v51_scan.py` 的包装（`runpy.run_path`；包装法的要点：改原脚本前先备份、改后用"回放前后账本逐字段对比"做回归）。

**stdout 协议（定时任务据此判断；下例全部数值均为占位符）**

```
V51 扫描 <MM-DD> <HH:MM>｜池<N>只｜最后K线 <YYYY-MM-DD> <HHMM>｜取数 {'sina': <N>} 失败0｜<t>s
今日新买点 1｜待执行 1｜今日成交 0｜持仓 3｜净值 <示例净值>｜已平仓 1
NEW_SIGNAL <YYYY-MM-DD> <HHMM> 999001.SH 示例银行 二买(破一买) 失效价<示例价>      ← 本根新确认的买点
PENDING {...}                                                               ← 下一根开盘待执行单（含取消条件与预检）
FILL ('<YYYY-MM-DD>','<HHMM>','999002.SH','示例保险','买',<示例价>,'一买 档位修复期 股数<示例股数>')   ← 纸面成交
报告： …/live/reports/V51_latest.md
```

## 2. 账本 `v51_ledger.json`

| 键 | 内容 |
|---|---|
| `asof / start / cfg` | 运行时刻、起点、配置快照 |
| `nav / cash / peak / streak / dead` | 净值、现金、历史高点、连亏计数、是否本金底线停用 |
| `positions` | `{代码: {shares, entry, stop, stop_adj, cost, typ, ent_dt, state, sig_bar…}}` |
| `pending` | 待执行单：`kind(买/卖)、code、typ、bar、ref(参考价)、stop、cancel_hi(=ref×1.03)、limit_up、shares、why(预检结果)、state` |
| `trades` | 已平仓：`ent/ext、entry/exit、shares、pnl、R、why(失效价止损/三卖/趋势一卖/持满120日到期)、state` |
| `fills / signals` | 全部成交 / 全部确认的买点（含 `ext_bar` 结构极值时刻、`sig_close`、`stop`） |
| `skips` | **被闸门拦下/取消的信号**及原因（`入池前确认，不计`、`ST`、`20日均额…<1亿`、`档位禁开(退潮期(hard))`、`熔断…`、`冷却期3日`、`已持仓`、`止损距离…>12%`、`带宽<1…`、`不足一手(风险预算股数…)`、`档位仓位余量不足`、`开盘高开>3%取消`、`开盘涨停取消`、`开盘已破失效价取消`…） |
| `equity_by_day` | 每日 15:00 的净值 |
| `health` | `src`（各数据源取到几只）、`fail`（失败的票及原因）、`fetched`（新增 K 线数）、`stale`（落后于最新 K 线的票） |

**信号延迟记录**（日报末节）：回测假设"信号确认后下一根开盘即成交（0 延迟）"。回测里晚 1 根 K 线买入年化约 7.5%→5.5%，所以**超过 30 分钟的信号要在执行卡上单独标注**；盘中扫描任务可能有数十分钟的启动延迟，这是需要接受并如实记录的偏差。

## 3. 日报 `V51_latest.md` 各节

1. 标题与性质（纸面、真实下单系数、起点、本金）；引擎 md5（确认用的是含修复的版本）；**池子变动**（入池时刻、入池前确认的买点不计）。
2. **数据健康**：最后一根 K 线、取数源、失败只数、新增 K 线数、落后只数。
3. **档位（前一交易日收盘，来源 pipeline/regime_YYYYMMDD.json）**：名称、总仓位上限、风险倍率。
4. **今日新确认的买点**表：确认时刻、股票、类别、结构极值点、信号收盘、失效价、处置（已挂单/已成交/被什么拦下）。
5. **待执行单**：方向、参考价、失效价、**取消条件**（开 >参考价×1.03 或 ≥涨停或 ≤失效价）、记账股数（满额口径）、预检。
6. **今日成交（纸面）**、**持仓与失效价**（含除权后换算的当前失效价、距失效价%）。
7. **账户**：净值、本金、历史高点回撤、已平仓笔数、连亏计数、熔断状态；最近 15 笔平仓。
8. **被闸门拦下/取消的信号（最近 20 条）**。
9. 说明：成交价＝下一根开盘±10bp；费用；起点前的信号不计；多个买点按代码顺序处理；盘中只用已收盘 K 线。
10. 信号延迟记录（累计）。

**待执行单预检**（`pending_precheck`）：用最后状态近似算档位/带宽/仓位，**只用于展示，不改账**；真正成交时由重放按成交那一根的状态重新过闸门。

## 4. 每日作业流（实盘使用者视角，实时回测期同样适用）

```
18:35  收盘任务：close_pipeline（日线→档位）→ v51_scan（日报）→ trin_daily（可选）→ 次日待执行单
9:25   看集合竞价：待执行买单若开盘价 > 信号收盘×1.03、≥涨停、≤失效价 → 取消；卖单照卖
9:30   执行待执行单
10:02  11:02 …  盘中扫描：有 NEW_SIGNAL/PENDING/FILL → 通知 → 下一根开盘执行
15:02  最后一根收盘：执行顺延到次日 9:30，列入待执行单
```

实时回测期 `stage_real=0`：**一律只记纸面、不下真单**。进入小仓之前必须先有使用者书面确认（具名例外与机制验收，见 [09](09-rollout-and-acceptance.md)）。

## 5. `pool_watch`：只读遍历

不写账本、不改 `m30_ext`，用于"问一下现在池子里谁离买点近"。`python3 pool_watch.py` → JSON → `pool_watch_report.py` 出 md。报告五节：①结论（按"离买点多近、该档位下买不买得了"挑出值得盯的票）②临近买点（每条写"还差什么才确认"）③近 10 个交易日已确认买点及现状（仍有效/已失效/出过卖点，以及"当时按 V5.1 能不能买"）④30 分钟强弱排序（未回测）⑤口径与局限。
与账本的核对行：本次遍历里 `start_date` 之后确认的买点集合，必须与 V5.1 账本 `signals` 一致，不一致要查。

## 6. `week_replay`：挪起点的情景回放

问"这周/这个月按系统买卖点虚拟买卖会赚多少"时：**先报正式账本，再用 `week_replay.py START "ASOF" TAG` 给情景**，并注明"池子是事后挑出来的强势票，回放收益有挑票偏差"。只写 `live/state_<TAG>/`。历史阶段的档位用 `pipeline/regime_history.csv`（`regime_daily.py --history` 生成），之后用实时的档位文件。
