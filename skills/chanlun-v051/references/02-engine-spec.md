# 02 · 引擎规格（分型 → 笔 → 线段 → 中枢 → 买卖点）

> 代码：`scripts/engine/lvl_engine.py`（`fractals()`、`macd()`）、`scripts/engine/sop_engine.py`（`pen_events()`、`find_seg_end()`、`Walker`、`analyze()`）、`scripts/engine/sop_run.py`（`run_series()`）。
> **人工看图只用来核对，不能覆盖引擎结论。** 引擎的行为是回测与实时扫描共同的依据：改它＝改交易系统，须先走预登记与回归测试（见 [10](10-discipline-and-verification.md)）。

## 1. 级别与数据

- **次级别 l＝30 分钟线段；操作级别 L＝由线段构成的中枢**（SOP 称"日线 L"）。机械化之后，一个 L 级中枢从开始到形成中位约 **42 个交易日**，所以节奏是"两个月左右一个结构"，不是普通日线节奏。信号很稀：池 64 只、6 年，一买原始事件只有约 50 个。
- 数据：30 分钟 K 线。**不复权价 × 当日日线复权因子 ＝ 前复权价**（与日线同口径）。MACD 用 30 分钟收盘价 (12, 26, 9)，跨日连续计算。
- **只用已经收盘的 K 线**；每根 K 线收盘后引擎推进一步。K 线时间标签＝结束时刻（`1000` 是 9:30—10:00 那根）；一天 8 根：1000/1030/1100/1130/1330/1400/1430/1500。
- 收盘判定带 +8 秒缓冲：`K线标签时刻 + 8 秒 <= 现在` 才算已收盘（`v51_scan.complete()`）。

## 2. 分型与笔

1. **包含处理**：相邻两根 K 线一根完全包住另一根（高低点同向包含）时合并。合并方向取决于上一次"非包含"时的走势：上一根合并 K 线的高点被新 K 线刷新＝向上（`dirn=1`），否则向下（`dirn=-1`）；向上合并取"高高、低高"（高点取大、低点取大），向下合并取"低低、高低"（低点取小、高点取小）。开头还没有方向（`dirn=0`）时按向上处理（`dirn >= 0`）。
2. **分型**：中间那根合并 K 线的高点比两边都高为顶分型，低点比两边都低为底分型；**右侧那根 K 线出现时才算确认**（`avail` ＝右侧 K 线序号）。
3. **成笔**：相邻的反向分型，合并 K 线序号差 ≥4，且顶高于底，成一笔；同向分型出现更极端的，笔端点延伸到新的极值（事件流里记为 `ext`）。

## 3. 线段

1. 线段从一个已确认的端点开始，至少包含 3 笔。
2. **上升线段**：跟踪线段内最高的顶；其后第一个回撤底记为 r1；**之后出现比 r1 更低的底、且期间没有创新高** → 线段在最高顶处结束，在那个更低的底被确认的时刻生效。下降线段镜像。
3. 不足 3 笔就被反向破坏、且价格破坏了线段起点的，视为前一线段延续（短线段作废，`revoked` 计数）。回测里 2,910 个线段端点只有 17 个被这样改写。
4. **线段"永久卡死"缺陷修复（重要）**：`Walker.push` 按（类型, 极值K线序号）找 `seg[-1]`；若 `seg[-1]` 指向的笔端点后来被**同向更极端的分型延伸**，旧版找不到它，从此**永久不再生成任何线段/中枢/买卖点**。影响面：原 64 只池里 40 只、256 只回测样本里 160 只、全市场约 62% 的票从 2020 年起整段 0 事件。修法：被延伸的正是 `seg[-1]` 时，`seg[-1]` 跟着延伸（`fixed` 计数）。没卡死的票这种情形从未发生，所以修复前后事件逐项相同。**任何引用 V5.x 回测数字的地方，都以修复后的复跑为准。**

## 4. 中枢、趋势、背驰

- **中枢**：连续三个线段的重叠区间，`ZG`＝三者高点的最小值，`ZD`＝三者低点的最大值，要求 `ZG > ZD`。后续线段只要没完成"离开＋回试不回"，就算中枢延伸，ZG/ZD 不变。
- **离开**：向上线段高点 > ZG（向下线段低点 < ZD）。向下线段低点跌破 ZD，中枢以"向下离开"结束。
- **下跌趋势**：相邻两个都以向下离开结束的中枢，后一个的 ZG 低于前一个的 ZD（不重叠）。
- **背驰**（一买用）：后一个中枢的向下离开段 c，与前一个中枢的向下离开段 b 比：**c 的低点更低；c 段 MACD 绿柱面积小于 b 段；c 段 DIF 最低值高于 b 段**。三条同时成立。
- **盘整背驰候选 `B1r`**：只有一个中枢，以"中枢第一个单元之前的下行单元"作为进入段做同样比较——只记录，不开仓。

## 5. 买卖点事件（`run_series` 的输出）

`run_series(h, l, c, "S")` 返回 dict，每个事件是 `(确认K线序号 k, info)`：

| 键 | 含义 | info 关键字段 |
|---|---|---|
| `B3` | 三买 | `ZG, ZD, lo`（回试低点）, `e_idx`（回试终点 K 线序号）, `s_idx` |
| `B1` | 趋势背驰一买 | `lo`（新低）, `e_idx`, `s_idx`, `idx_unit`, `n_unit` |
| `B1r` | 盘整背驰候选（不开仓） | 同 B1 |
| `B2c` | 二买（不破一买） | `lo`（回试低点 P3）, `p1`, `e_idx`, `p1_idx` |
| `B2w` | 二买（破一买） | 同 B2c |
| `S3` | 三卖（镜像序列上的 B3） | 同 B3（价格取负） |
| `S1` | 趋势一卖（镜像序列上的 B1） | 同 B1 |
| `NEWP` | 新中枢形成 | `ZG, ZD, first_s, i0` |
| `revoked / fixed / n_units` | 线段端点被改写数 / 缺陷修复触发数 / 线段数 | |

- **卖点用镜像**：把端点序列价格取负、类型互换，再调用同一个 `analyze()`。
- **二买基于一买**：在一买低点之后找"上一段、下一段"：`P3 > P1` 记 `B2c`，否则 `B2w`。
- 事件去重：同一 `(类型, e_idx)` 只记第一次出现的 K 线序号。

## 6. 失效价与确认滞后

- **失效价＝`info["lo"] × 0.99`**（前复权价），换算回不复权价：`÷ adj[e_idx]`；持有期间不移动。
- **确认滞后**：确认的那根 K 线通常比结构极值晚约 **34 根 30 分钟 K 线（≈4 个交易日）**，此时价格通常已离开低点，所以止损距离中位约 7%。
- **前视的代价**（为什么必须用确认时刻的数据）：同样的买点规则，只把成交时点从"确认时刻"挪到"结构极值那根之后"（相当于软件图上事后画出的箭头），关注池上的平均 R：一买 0.63→3.43、二买 1.25→5.13、三买 0.95→6.13（夸大 2—9 倍）。**任何入场价、失效价、R 都必须从确认时刻的数据算。**

## 7. 无前视自检（截断重算）

对任意时刻 T，把数据截到 T 重算，已发出的信号必须与全量结果**完全一致**。本地引擎历史上 672 组（30 分钟）、1,344 组（日线）、2,016 组比对 0 差异。仓库里的自检：`tests/test_engine_truncation.py`（用合成随机游走数据，不依赖任何行情文件）。

## 8. 已知的口径细节（实现时容易错）

- **价格过 A 不等于确认**：向下线段"上-下-上"的确认要求第三笔够根数成笔；盘中价格超过 A，只是第一笔延伸、A 跟着抬（示例：某票盘中价略高于 A 点，仍可能未确认）。
- **"临近买点"是观察口径，不是规则**：把进行中的向下线段假设在当前最低点结束，用同一引擎算会不会出一买/二买/三买；回看确认率：临近三买 64%（20 个交易日内确认，中位 7 天）、一买 67%（8 天）、二买 78%（8 天）。只验"会不会确认"，没验盈亏。
- **数据拼接的类型坑**：CSV 读进来 `time` 是整数、实时源是字符串，先 `concat` 再 `drop_duplicates` 会去重失败（每只多出 11 根重复 K 线，均线/MACD 全偏）。任何"内存数据＋CSV"合并，先把键统一成 `"%04d"` 字符串再去重，并断言无重复。
- **除权**：引擎用前复权价，挂单用真实价；失效价随复权因子换算（`stop_adj / adj[-1]`）。
