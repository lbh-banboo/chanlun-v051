# 05 · 池文件格式契约（改池文件前必读）

`pools/watchlist.md`（池A）与 `pools/focus.md`（池B）都是**被脚本用正则解析的 markdown**：`v51_scan.py`、`pool_watch.py`、`pool_tool.py` 三处共用 `scripts/_common.py` 里的同一份解析实现。
**违反契约不会报错，而是静默污染下游**（名称错、簇数虚高、入池前信号被计入账本）。改完先跑 `python3 scripts/pool_tool.py check`。

## 必须遵守的 5 条

1. **名单表名称列不得加粗**。`**名称**` 会被解析成名称本身带星号，静默污染全部下游标的名称。（行业分组行 `| **电子（20 只）** | | | | | |` 可以加粗——它不带代码，不进名单。）
2. **名单表须在 `## 名单` 节内，且为六列**：`名称 | 代码 | 板块 | 加入日期 | 入池来源 | 状态`。行业分组行不带代码。代码格式 `999001.SH` / `999003.SZ`（六位数字＋交易所后缀；示例为占位代码）。
3. **主题簇表须含「主题簇」「成员」两个表头**；成员用顿号（、）分隔，**名称与名单表完全一致**（不一致的成员被静默忽略，簇的 30% 上限就少算一只）。⚠ **识别到该表头后，解析器会对其后所有表格行持续解析**——所以**主题簇表之后不得再出现其它表格**（核查清单、裁定清单、留档索引一律改成列表）。
4. **冷却期说明与「最早 YYYY-MM-DD 可买回」必须写在名单表对应标的的同一行内**（逐行匹配，且要求日期 > 今天才算在冷却期）；已过期的写「冷却期已解除」。无法核定卖出日/价的，写「冷却期无法核定，视同仍在冷却期」（按最保守口径视同冷却）。
5. **名单只认 `## 名单` 节内的行**。本仓库的解析器按节切分，名单节之外的 `| 股票 | 代码 |` 表不会被当成名单；但其它下游（如日报生成器）可能按表头识别名单表，会让名单只数虚高——若你要与其它工具共用池文件，核查类表格请避开"股票 | 代码"这两个表头词并列，改用列表。

另外：
- **「加入日期」列**写 `YYYY-MM-DD`（当天收盘后入池）或 `YYYY-MM-DD HH:MM`（盘中入池）。带「前」字（如 `2025-06-01 前`）表示**不设限**，只给实时回测起点之前就在池里的存量票用；起点之后新增的票**不要写「前」字**，否则入池前确认的买点也会被计入账本（`pool_tool.py check` 会对起点之后的日期带「前」字给出提示）。

## 可选：`## 簇叠加` 节

保守口径下，申万不同一级但驱动相同的票要叠加计量 30% 上限。把这些规则写成**声明**，而不是写死在代码里：

```markdown
## 簇叠加
- 股票「示例GPU」→ 簇「半导体—设备/封测/设计」
- 簇「半导体—材料」→ 簇「半导体—设备/封测/设计」
```

- `股票「名称」→ 簇「目标簇」`：该名称的票**额外**计入目标簇。
- `簇「源前缀」→ 簇「目标簇」`：簇名以"源前缀"开头的所有成员**额外**计入目标簇。
- 只在 `v51_scan.py`（计量主题簇 30%）里生效；`pool_watch.py` 的预检不用簇。

## 主题簇与 30% 上限

- 同一主题簇（含叠加）的持仓市值合计 ≤ 净值的 30%（`CLUSTER`）。**约束的是持仓市值，不是池内只数**。
- 申万三级相同 ≠ 同一主题簇；申万拆在不同一级的同产业链（如 AI 算力的服务器 PCB、液冷、IDC）要手工归簇，并在"为什么归在一起"列写依据。
- 归簇口径有争议的，写进"待裁定清单"，**裁定前按最保守口径合并计量**。
- 申万二级/三级板块**一律取数**，不得按印象填；整列统一口径，换口径必须整列一次性替换。

## 常见错误速查

| 现象 | 原因 |
|---|---|
| 日报"池内 66 只"但你只有 65 只 | 名单表之外还有同形状的表（`| 股票 | 代码 |`），或主题簇表后的表格行被当成簇行 |
| 某只票永远没有簇、不受 30% 约束 | 主题簇表里的成员名称与名单表不完全一致（全角/半角、空格、"Ａ/A"） |
| 新入池的票立刻有历史"信号"被记账 | 「加入日期」写了「前」字，或没写日期（解析不到＝不设限） |
| 冷却期不生效 | 没按「最早 YYYY-MM-DD 可买回」写；或写在名单表之外 |
| `pool_tool.py add` 报名称不一致 | 行情源返回的实体名与输入不同——先向使用者确认，别直接采用返回的代码 |
